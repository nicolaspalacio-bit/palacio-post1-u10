# ADR-001: Seleccion del Entorno de Analisis Estatico (SonarQube vs SonarCloud)

## Estado
Aceptado

## Contexto
El microservicio `envios-service` requiere la ejecucion de inspeccion estatica de codigo y auditoria continua de metricas de calidad de software (complejidad ciclomatica, duplicacion, reglas de estilo y code smells). Es imperativo seleccionar y justificar una plataforma de analisis de calidad de codigo segun los criterios de autonomia operativa, costo computacional, facilidad de despliegue y compatibilidad con el entorno de trabajo.

## Decision
Se adopto una configuracion de operacion dual:
1. Se configuro el archivo `sonar-project.properties` y el plugin de Maven `sonar-maven-plugin` (version 3.11.0.3922) apuntando por defecto al puerto estandar de SonarQube (`http://localhost:9000`), permitiendo a cualquier desarrollador ejecutar el contenedor oficial de SonarQube mediante `docker run -d --name sonarqube -p 9000:9000 sonarqube:community`.
2. Paralelamente, las propiedades estan estandarizadas para permitir el analisis administrado en SonarCloud (`https://sonarcloud.io`) sobre el repositorio publico de GitHub `palacio-post1-u10` mediante el paso de parametros en linea de comandos (`-Dsonar.host.url=https://sonarcloud.io -Dsonar.organization=... -Dsonar.token=...`).

## Alternativas Descartadas
- **Depender exclusivamente de SonarQube con Docker en local:** Se descarto como unico mecanismo debido a que entornos de desarrollo locales en Windows que carecen de Docker Desktop o de privilegios de virtualizacion WSL2 quedarian bloqueados para ejecutar la compilacion y medicion. Adicionalmente, el contenedor de SonarQube requiere un consumo intensivo de recursos (minimo 2 GB de RAM dedicados a su instancia de Elasticsearch).
- **Depender exclusivamente de SonarCloud en la nube:** Se descarto como mecanismo unico para preservar la autonomia del proyecto ante ausencia de conexion a internet o limites de velocidad en redes corporativas/academicas.

## Consecuencias
- **Positivas:** El proyecto no impone barreras de entrada; funciona tanto en entornos con Docker local como en pipelines de CI conectados a SonarCloud. Las propiedades se mantienen centralizadas y reproducibles.
- **Negativas:** Requiere mantener alineadas las claves de proyecto (`sonar.projectKey=com.universidad:envios-service`) entre ambos entornos.
